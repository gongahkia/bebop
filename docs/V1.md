# v1 scope

v1 freezes Bebop's current agent-less, reviewed-host-management scope. It is a
boundary for maintenance and review, not a promise that no later major version
can add capabilities.

## Included

v1 includes host inventory; local and SSH target resolution; inspect,
bootstrap, doctor, status, deterministic plan/apply, and saved-plan apply;
the reviewed platform matrix and its package-manager/init combinations; the
Bebop data root; automatic updates only where the platform policy permits
them; Docker Engine and Compose V2; Tailscale daemon lifecycle without
authentication; SSH hardening; explicit storage placement and managed mounts;
strict Compose services and secret environment references; backup, restore,
and migration through backup plus restore; embedded recipes; controller-side
maintenance and notifications; and the existing bounded multi-host read
operations.

## Deliberately outside v1

- arbitrary shell commands, package operations, repositories, or plugins;
- target-side agents, Kubernetes, Podman abstraction, or firewall management;
- partitioning, formatting, resizing, automatic disk selection, RAID/LVM,
  encryption provisioning, Docker-root relocation, or live-data migration;
- generalized transactions or rollback, overwrite restore, or arbitrary remote
  service-source acquisition;
- distributions added merely for breadth. Gentoo remains unsupported until its
  reviewed binary-package/Tailscale provenance blocker is resolved; NixOS
  requires a separate architecture decision.

The exact reviewed target contract remains [SUPPORT.md](SUPPORT.md). Changes
to that matrix are maintenance work only when they follow the documented
platform review process.
